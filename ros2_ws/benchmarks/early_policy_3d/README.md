# 早期集中式策略的三维传感对照适配

用户要求将早期约 300 秒的策略接入当前三维传感环境，按相同三维覆盖率评估。历史基线为 `7136591` 的集中式 GVP＋成对任务优化（办公室一次运行 259.5 s）；这里没有重新使用旧理想射线传感器或二维覆盖率。

`vendor/` 的五个文件逐字来自该提交，`provenance.json` 保存版本和 SHA256。`adapter.py` 只在独立基准进程中注入以下维度适配；生产融合入口及其默认行为不变。

| 环节 | 本次做法 |
|---|---|
| 任务分配与顺序 | 原 `SearchCoordinator` 和 `allocate`，最近图距离初分配、原有限次转移/交换、原目标函数、固定当前任务 |
| 前沿目标 | 原未知邻域计数及 2 m 间距、最多 24 点；平面 2 m 圆盘扩为 3D 球，距离前沿 1.6 m；工作量仍为 `1 + gain × 0.01`，未重新调参 |
| 图 | 原全自由栅格图从四邻接扩为六邻接；它不是 MR-DTG，也不称为稀疏拓扑 |
| 路径质量池 | 原 A*＋惩罚多路径的已有三维索引扩展，原评分和最多五条备选 |
| 有限视场朝向 | 保留旧策略选出的目标位置，仅用 12 个偏航方向的 120° 未知体素计数选择目标偏航；没有接入融合版观测位姿搜索 |
| 感知与定位 | 与优化版相同的原生 GPU LiDAR、点云映射器、IMU＋带噪定位 EKF；各机实测地图输入集中式旧调度器，保留旧版共享地图架构 |
| 地图与计量 | 同一 `search_fusion_3d.json`、0.3 m 体素，完全自由体素分母 58589；沿用原三维评估器，真值不进入调度器 |
| 动作执行 | 共用连续轨迹拟合及执行器、0.6 m/s、0.8 m/s²、jerk 2 m/s³、偏航 0.65 rad/s、0.7–3.1 m 高度、原安全净空；共用短距离安全恢复 |
| 提交契约 | 保留集中授权，由真实独立客户端转发；不伪造邻机 ACK，不宣称去中心化 |
| 计算 | 独立工作进程避免阻塞 ROS 心跳；每次仍按旧策略最多为一架空闲机派单，没有下一视点预规划 |

暂停 25 s、18 s 规划通信中断、动态圆柱采用当前评估器的相同触发规则。**进程重启有不可消除的架构差别**：旧集中式策略没有每机规划器，所以重启的是真实每机命令客户端，中央规划器持续运行；不能将此作为与融合版单机规划器重启等价的消融。规划通信中断时，旧客户端停止接收中央命令，中央停止接收该机地图；独立本地安全定位仍保留。

这是一组披露适配范围的工程对照。旧版原本固定高度、全向感知，不可能在完全不适配的情况下完成同一个三维传感任务；结果不能记为原始提交在原条件下的运行成绩，也不能将维度适配后的差异全部归因于任务分配器。

## 预先设定的运行与停止条件

- 从冷启动录制一次正式尝试；开始前先单独做 60 s 接口启动检查，该检查不计入任务性能结果。
- 达到 95% 后保持至少 3 仿真秒；碰撞、越界或持续 1 s 的意外落地 / 跟踪误差 >0.8 m 停止并保留失败记录；不把接触计数为零单独当作安全证明。
- 正式运行上限：初始扫描完成后 **2400 仿真秒**，墙钟最多 14400 s。到限仍未达到 95% 就报告未完成，不使用二维覆盖率提前宣布成功。
- 完整录制源码快照、原始轨迹/跟踪/点云地图、候选与分配日志全部保留；视频只做明确倍速及标题，不伪造轨迹动画。
- 分别报告覆盖率、时间、总航程、接触、运动占比、故障完成情况；每版本一次运行，不声称统计显著性。

## 复现

在已构建当前 ROS 工作区且装好 Xvfb/Openbox/ffmpeg/RViz 的 Linux 环境运行：

```bash
source /opt/ros/jazzy/setup.bash
source ros2_ws/install/setup.bash
export PYTHONPATH="$PWD/next_project:$PWD/ros2_ws/src/annual_swarm/scripts:$PWD/ros2_ws/benchmarks/early_policy_3d:$PYTHONPATH"
OPENBLAS_NUM_THREADS=1 python3 -m pytest -q ros2_ws/benchmarks/early_policy_3d/test_adapter.py
python3 ros2_ws/benchmarks/early_policy_3d/run.py \
  --output-dir /tmp/early-policy-3d --simulation-limit 2400 --wall-limit 14400 --speed 24
```

运行目录必须不存在。读取 `run-result.json` 区分完成、时限、真实失败和基础设施故障；`summary.json` 保留评估器实测状态。不可将一次未完成运行包装为完整验收。

接口联调记录：完成状态从瞬时 reason 改为持久的 epoch/arrived/trajectory_time；旧策略的撤销命令显式转发到执行授权。一次三维尝试在客户端重启后发生三机失稳，保留为失败记录；其接触计数未报警，不能计作安全飞行或性能完成。后续客户端移除无用的规划/SciPy 导入，减少重启开销，并加入独立执行失稳停止条件；尚未将该失稳原因归结为任务分配算法。
