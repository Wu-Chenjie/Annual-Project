# 融合式多无人机三维探索

入口 `decentralized_search.launch.py` 运行一条融合流程，没有 RACER/GVP 模式选择器：

**实际点云 → 私有三维地图/增量前沿 → 自适应 Hgrid/EROI → 增量 MR-DTG → 局部与全局图 Voronoi → 双机容量约束任务/路线协商 → 区域顺序引导的观测位姿搜索 → 候选轨迹质量评估 → 连续轨迹 → ROS 控制器 → Gazebo 电机动力学。**

本仓库独立实现所引用的算法思想，依据 [RACER](https://arxiv.org/html/2209.08533v1) 和 [GVP-MREP](https://arxiv.org/html/2408.05808v1)。这是融合工程实现，不能等同于两篇论文的逐行移植、实机系统或论文指标复现。历史平面版本的录像和数据继续保存在 `docs/validation/decentralized/`，不得作为本版本的三维验收结果。

## 算法如何结合

| 环节 | 当前实现 | 主要文件 |
|---|---|---|
| 感知与估计 | 原生 Gazebo GPU LiDAR，181×31 射线、120°×120°、4.5 m、5 Hz；点云按估计位姿变换，概率占据更新；IMU 与带协方差定位测量融合 | `pointcloud_mapping_node.py`, `state_estimation.py` |
| 分层区域 | 8/4/2 m 自适应 Hgrid，稳定三维区域 ID，已提交区域固定；前沿局部更新、连通簇缓存；区域及持久视点状态 | `hierarchy.py` |
| MR-DTG | 实际飞行历史节点、有限半径 Dijkstra 树、树交叠握手折线；每个可达 EROI 挂接一个历史节点；跨机图增量合并、缺包快照修复、障碍边否决、区域服务反馈与观测存在性回执 | `mrdtg.py` |
| 图分区 | 沿图上真实走廊距离计算局部 EROI 与全局历史节点 Voronoi，决定初始服务归属 | `mrdtg.py:graph_voronoi` |
| 任务与路线 | 双机交换窗口上联合行驶时间/信息等待时间的子集动态规划及容量约束划分；窗口之外的任务计入固定负载；已执行区域固定；版本化 prepare/accept/commit/applied 协商 | `pairwise.py`, `fusion.py` |
| 分层搜索 | 按可见新增量、未知连通块规模和有界等待系数估计收益；插入与 2-opt 联合优化路线长度与高收益任务完成时间，保持优化后的区域顺序；本地做位置/偏航两步搜索，远程通过 MR-DTG 走廊推进已观测前缀 | `fusion.py`, `priority.py`, `regions.py` |
| 观测/运动 | 信息收益按每条射线的首个未知体素计算，考虑遮挡；两步观测去重，联合平移、偏航、路线质量与下一服务区域出口代价 | `regions.py:ObservationPlanner` |
| 轨迹 | 共用质量评估器评估多规划器/单规划器多候选，保留至多五条有效备选；固定路径节点的最小 jerk 五次样条、段时间优化、速度/加速度/jerk 极值验证、偏航连续与控制前馈 | `path_quality.py`, `continuous_trajectory.py` |

双机精确求解只针对最多 10 个区域的交互窗口（求解器硬上限 12），不是全机队全局 CVRP 最优。窗口外负载计入容量，但其完整路径并不同时进行穷举优化。前沿检测增量更新；连接簇标签仍整体重算以处理分裂/合并。连续轨迹使用本仓库五次样条实现，不冒充原版 MINCO 或 RACER 的 B 样条优化器。

## 飞行期间的下一视点预规划

融合规划与连续轨迹拟合在每机独立的 `spawn` 工作进程中运行，ROS 主进程继续处理观测、心跳、预约和撤销。执行当前视点期间，后台从当前轨迹终点预测下一任务/视点；历史节点仍记录实际位置，不能把尚未到达的终点写成飞行历史。下一视点的预测信息收益扣除当前视点预期看到的首个未知体素，并保留原来的两步观测搜索。

抵达后才允许采用预规划结果：检查实例内 epoch、结果时效、当前位置、区域服务暂缓状态、最新归属和全部实时预约，再重新验证候选池。连续曲线只有在活动候选未改变、起点误差不超过 0.08 m、偏航误差不超过 0.12 rad 且连接段与整条曲线在当前地图中安全时才能复用，否则重新拟合。仍须经过原预约确认和提交前复查。撤销、重启或动态障碍不会提前授权下一条路线。

计算开销通过以下方式降低：区域插入及有向 2-opt 使用边代价增量；同一规划快照的拓扑接入点查询缓存；三维局部有限半径搜索使用稀疏矩阵 Dijkstra；历史树及握手仅在对应搜索包围盒内的占据/未知几何或膨胀安全格变化时重算；已构建的碰撞场按地图内容与配置复用。缓存不以传感版本号单独判断有效性，直接修改地图以及新障碍均有失效回归测试。

`fusion.stage_wall_s` 分别记录地图、分层区域、拓扑、探索优先级（`priority`）、路线、双机窗口、视点和轨迹拟合的墙钟耗时。`next_view_ready` / `next_view_adopted` 和 `prepared_trajectory` 区分后台准备、抵达后采用与连续曲线实际复用。旧版本的 `compute_wall_s` 不包含 ROS 回调中的轨迹拟合，比较时需注明这个统计范围差异。

若新观测使当前位置不满足常规余量，且不存在经过机体包络验证的短距离恢复路线，代理发布 `motion_blocked=true`、停止竞价并标记暂不可服务。它仍感知、确认已有预约、同步拓扑和处理任务转交，每 10 s 刷新一次完整规划快照；不能因为无法运动而把整条协作链路提前退出。再次具备安全运动条件时自动恢复竞价。`motion_suspended` / `motion_resumed` 记录这个过程。该机制提供安全悬停和任务接管，不保证从任意保守地图重叠状态自动脱困；进程重启成功也不能等同于已恢复飞行。

## 未探索区域优先级

`priority.py` 在每架机的观测地图上，按面邻接聚合未知体素。组件体积是未知空间估计，可能包含未发现的墙体，不能称为可通行自由体积。组件编号只在当前快照内有意义；等待时间依附稳定的 Hgrid 区域 ID，细分时继承已记录的父区域等待起点。

区域候选选择采用以下收益分数，不写入碰撞代价：

```
R = repeat_factor × net_visible_volume × (1 + 0.35 × log(1 + component_volume / 8))
    × (1 + min(0.5, 0.15 × waiting_seconds / 60))
P = R / (1.5 + route_distance / 0.6)
E(route) = physical_time + 0.5 × sum(R_i × completion_time_i) / sum(R_i)
```

P 用于区域候选、双机交换窗口及无人认领时的分担选择。主要访问路线在同一目标 E 下做最小增量插入和有向 2-opt；完成后直接使用这个顺序，不再按 P 重排。R 使用信息量，避免路线目标重复除以距离。本机预计服务时间为 `1 + unknown × 0.012` 秒，双机小窗口使用统一 1.5 秒服务估计；这些是路线比较代理量，并非飞行完成时间的保证。返回的 workload 仍是物理运动与服务时间。

每轮最多细化 24 个区域，其中 4 个名额优先给最久未刷新的区域，其余按本机归属和 P 选择。每区域最多两个安全前沿视点、各四个偏航方向，使用 21×5 粗射线。未变化的局部几何继续复用射线结果，失效但本轮未细化的区域使用明确标记为 `region_bound` 的区域收益估计。这个预算限制的是粗评估计算；实际被执行的视点仍经过原 61×13 三维射线搜索、最多五个视点/八个方向及路径和预约验证。缓存按射线窗口内的地图内容失效，新增障碍不能被旧缓存忽略。`priority_compute` 记录射线次数、细化、缓存及估计区域数。

视野只统计射线遇到的首个未知体素。`component_volume` 为该方向能触及的未知组件体积，按对数加权；到达距离来自已知自由空间路由/历史图。当前视点及三秒内新鲜、已提交、未撤销且非恢复路线的同伴终点视野，按集合并集从收益中扣除。同一体素不会重复扣减；过期意图不再提供收益折扣，安全预约仍独立保留。

此外，各机将实际传感器已观测格压缩为 256 位分块回执，经原有图增量协议同步。回执只有“观测过”这一位，不含自由/占据值；按地图几何标识匹配、按位 OR 合并，重复、乱序与重启沿用源实例/序号机制。历史已观测但本机仍未知的格保留 10% 收益，减少重复覆盖，同时允许为通行和末端清理进行必要的本地观测。历史折扣同时进入区域、组件与两步视点收益；采用预规划时再次检查。回执不修改本机占据地图、安全格或碰撞约束。没有本地地图证据的远程区域仍标为 `remote_proxy`，使用上限 1 m³ 的代理量引导安全走廊推进。

每次提交时记录区域内及跨区域预测视野中的未知格，完成后只对这些格计算服务新增量，避免无关区域的沿途观测掩盖反复低收益。低收益门槛为 `min(30, max(1, ceil(待观测格数 × 20%)))`，因此清理小残片也可视为成功。连续低收益的退避为 15、30、60、120 秒，之后封顶；收益乘以 `1/(1 + streak × exp(-距上次服务秒数/600))`。成功立即清零次数。远程走廊中途推进不产生失败反馈。

等待奖励最多将原收益乘以 1.5，不能独立产生收益或无限压过大区域；零预测收益、不可达区域不能靠等待变成可执行任务。服务后重新计时。当前已提交飞行继续执行，下一视点决策重新联合优化收益与路线，不因优先级变化中途抢占飞行。未知体素、机体净空、动态障碍及多机预约仍是硬约束。

参数集中在 `config/exploration_priority.yaml`，启动时可通过 `priority_config:=/absolute/path/to/config.yaml` 替换。`/drone_i/topology.exploration_priority` 仅向诊断/RViz 发布组件体积、优先级、等待时间和观测切片，`graph_delta` 不传这张地图。RViz 默认显示 UAV 0 的收益估计（参数 `priority_source`）：全队仍未知的区域用金色强调，越明亮表示相对优先级越高；全队已观测为自由、但本机仍未知的位置用淡紫色小格点显示。底图未知为深蓝灰、已观测自由空间为灰蓝、障碍为灰白。三架机在 Gazebo 与 RViz 中统一为天蓝、粉紫、翠绿；拓扑使用细灰蓝线，飞行轨迹与执行路线使用更粗的机体同色线。组件标签中的 `Local C` 体积仍属于指定无人机的局部未知组件，不能相加当成全局未知量。全队观测并集仅在可视化节点中用于颜色分类，不传入规划器；地图尚未收到或网格不匹配时图例明确显示 `Local unknown`。

[当前原生 Gazebo/RViz 配色预览与图例](docs/validation/display-palette/README.md)。

实现验证覆盖连通块分裂/合并、遮挡和缓存失效、较远大区域优先、同伴视野/历史回执去重与失效、有界等待、非对称路线增量与完整目标对照、精确子集路线穷举对照、粗评估预算与轮转、低收益退避与成功恢复、ROS 标记和反馈重启恢复。保存地图的离线计时只说明计算开销；尾段是否变快仍需同地图冷启动对照，以 90%→95% 耗时、重复观测和总航程评估，不能用单测或旧版本录像宣称性能改善。

## ROS 节点与数据接口

每架机各有以下独立节点：

1. `localization_measurement_node.py`：仿真定位测量适配器，向真值里程计加入位置/速度噪声及协方差。可替换为发布标准 `nav_msgs/Odometry` 的外部定位系统；它不是 VIO/LIO/SLAM。
2. `state_estimator_node.py`：IMU 预测、测量校正、异常测量门限、正定协方差。延迟定位先回溯到测量时间，再重放最多 200 帧 IMU；未来时间的测量等待 IMU 到达后处理。机体系速度和世界系速度显式转换。加速度模型不确定性使用连续白噪声离散化，同时传播位置、速度及其互协方差，避免采样 IMU 未包含完整地面接触冲量时持续拒绝有效定位。
3. `pointcloud_mapping_node.py`：订阅实际 `PointCloud2` 和本机估计位姿，仅维护本机占据地图。
4. `decentralized_agent_node.py`：本机地图、融合规划、区域协商、候选池及预约协议。没有集中任务分配节点。
5. `view_executor_node.py`：独立核验预约、跟踪连续参考、执行偏航和到点观测；误差过大暂停轨迹时间。
6. `controller_node`：当前融合演示使用 PID，输出真实电机转速。原有其他控制器和规划器入口保留。

|---|---|---|

| `/drone_i/map_bootstrap` | `String` JSON，session | 本机代理重启后请求映射器全量恢复；不是跨机地图共享 |

| `/experiment/control` | `String` JSON | 仅实验暂停、规划通信分区、指定旧实例重启和实验结束，不分配任务 |

区域服务结果通过图增量传给同伴并在本机重启后恢复，包括连续低收益次数及成功后的清零；以最新观测时间合并，旧失败的较长截止时间不会覆盖新成功。未知量较多的陈旧区域报告不能覆盖更充分观测后的完成/细分状态。

双机交换只纳入当前可竞价区域。接受提案后，参与方在断连期间保留锁并等待发起方的明确结果；已应用结果持续确认，防止迟到提交或确认丢失造成卡死。

图序列缺失时请求完整源快照；重复或乱序记录不会重复应用。新进程携带新的实例 ID，先取消旧执行、停稳、恢复本机地图，再以更大的 epoch 加入。旧实例消息被隔离。日志采用追加写入，统计按 `(无人机, 实例)` 累计，保留重启前的证据。

## 安全与恢复

- 常规路径需要固定成员的预约确认。确认方检查自己的路径/悬停位置、既有授权以及区域父子范围冲突。
- 断连不释放已确认预约。已提交路径持有原确认凭据；新路径只能在预先约定、留出间隔的本机 Voronoi 应急区域内执行，并继续避开保留预约。
- 当前故障试验切断的是规划状态/拓扑通信；独立的邻机状态安全输入仍存在。不能将此表述为所有链路同时失效下的验证。
- 撤销后保留预约，直到执行器确认对应 epoch、实际速度 <0.08 m/s 连续 0.5 s。进程重启也通过停稳确认隔离旧实例。
- 三维未知体素按障碍处理。常规水平余量 0.6 m、竖直余量 0.2 m；飞行高度限制在 0.7–3.1 m，避免从 3.5 m 高墙上方绕过迷宫。
- 同伴路径在本机路由中以 1.25 m 保留；预约协议采用保守的水平路径互斥。它没有实现允许交叉路线错时共享的完整时空多机轨迹优化。
- 短距离退让限距 0.65 m，固定偏航，限速 0.15 m/s、限加速度 0.2 m/s²；对机体包络与占据/未知体素做分离轴检查，再回到正常规划余量。没有清空未知地图来制造可通行区域。
- 新障碍到来先撤销失效路径，再核验原候选、预约备选或重新规划。平滑曲线碰撞时退回沿已验证折线的 C2 停点五次轨迹；日志明确记录使用的方法。

正常连续参考上限为 0.6 m/s、0.8 m/s²、2 m/s³、偏航 0.65 rad/s。这些是参考曲线约束，不是对有噪声刚体实际运动的数学保证；实际跟踪误差和接触必须另行检验。

## 运行与录制

```bash
source /opt/ros/jazzy/setup.bash
cd ros2_ws
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
ros2 launch annual_swarm decentralized_search.launch.py \
```

## 任务轨迹质量及证据

任务层记录未知空间工作量、区域访问顺序、协商前后代价、容量/负载、转交及实例恢复；路径层记录长度、净空、转弯、离散平滑度及联合观测运动代价；连续参考层记录真实多项式导数极值、时长和回退方法；执行层记录 Gazebo 真值与参考位置的 RMS/P95/最大误差、实际里程、偏航、高度变化、机间距离及接触。

双机窗口目标为 `J = E_a + E_b + 0.25 × max(E_a, E_b)`。每架机的 E 为预计运动/服务时间加信息加权完成时间；分母固定为整个交换窗口的总收益，避免因划分改变归一化尺度。子集动态规划同时优化区域归属与访问顺序，容量、执行中任务固定及窗口外负载约束仍须满足。区域负载为 `1 + 未知体素数 × 分辨率³`，并计入窗口外固定负载；这是探索工作量约束，不是电池续航模型。观测位姿则按未知体积收益除以平移、转向及驻留时间评分，再加入第二视点的增量收益与下一任务出口代价。

候选路线先过碰撞/未知空间硬门槛，再按固定物理尺度计算长度、净空、转弯、名义加速度及 jerk 五项，权重分别为 `1 / 0.8 / 0.15 / 0.15 / 0.05`。按弧长重新采样，避免路径采样密度改变排名；平均形状距离不足 0.25 m 的候选去重。实际可用路线不足六条时保留全部有效路线，不凑满五条备选。最终连续曲线另外检查真实多项式导数极值，飞行后再核对真值跟踪误差。

观测收益预测只计射线遇到的首个未知体素，属于局部信息代理量；实际新观测体素数另行记录。候选日志的历史字段 `gain_m2` 在三维运行中实际保存体素体积代理量，应按地图维度解释，不能当作平方米指标。

`summary.json` 中覆盖率是实际传感器已观测自由体素占几何上完全自由体素的比例。体素盒与 AABB/圆柱存在正体积交集时，真值将该体素判为占据，与点云地图的占据语义保持一致；边界体素盒裁剪到地图范围。这是体素格子比例，不是连续自由空间体积的精确积分。

旧评估器仅检查体素中心，会把与墙相交但中心在墙外的格子误判为真值自由，导致正确的保守占据地图也被扣覆盖率。修复后保留 `legacy_center_free_coverage` 供对照，不与新指标混用。`observed_final.npz` 保存完成时的传感地图，审计从原始场景几何独立重算覆盖率及分母；离网格边界 AABB 和圆柱均有回归测试。95% 触发的是实验结束，规划代理不读取真值或这个比例。当前并没有基于完全异步网络的分布式全局终止证明。

`peer_payload_bytes` 只累计公共状态与图同步的 JSON 应用负载，不包含 DDS/IP 开销；`graph_payload_bytes` 是其中图同步部分。它们不能直接与历史理想平面传感器的时间或通信数字作性能优劣比较。严谨论文对照需要同一传感器、地图、随机种子和计算平台的重复实验。

`audit_fusion_run.py` 对完成记录检验覆盖率、零接触、间距、三维高度变化、真实偏航、图稀疏度、双机容量、连续轨迹约束、预约证据、五条备选上限，以及暂停、规划通信恢复、动态障碍响应和进程重启。测试通过和运行通过分别报告，不互相替代。
