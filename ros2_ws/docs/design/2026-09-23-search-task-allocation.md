# 搜索任务分配与动态环境拓扑图设计

状态：设计原文保留供追溯；2026-09-23 已开始实现集中式观测地图搜索原型。实际已实现范围、简化与验收以 [EXPLORATION.md](../../EXPLORATION.md) 和 [VALIDATION.md](../../VALIDATION.md) 为准，不能将下文全部设计目标视为已经实现。

## 参考依据与边界

- [RACER 论文](https://arxiv.org/abs/2209.08533)：在线 hgrid 空间分解、成对交互、CVRP 工作量与覆盖路线优化、分层探索规划。
- [RACER 源码](https://github.com/Robotics-STAR-Lab/RACER/tree/049c332e3634ef72d8beb155b4c13dc91ca52916)：核对了 active_perception/hgrid、exploration_manager/src/fast_exploration_manager.cpp 的 allocateGrids，以及 fast_exploration_fsm.cpp 的 PairOpt 请求、响应和时间戳一致性检查。不是简单的“最近目标分配”或单轮匈牙利匹配。
- [GVP-MREP 论文](https://arxiv.org/abs/2408.05808)：MR-DTG 表达已探索与探索区域；以实际运动代价进行图 Voronoi 分区；通过紧凑图信息降低通信需求。
- [GVP-MREP 源码](https://github.com/NKU-MobFly-Robotics/GVP-MREP/tree/f5865b9c9c39e9d85095555f3e04b4fa349fce40)：multiDTG/dtg_structures.h 区分 H_node、F_node 和连接边；graph_partition 独立承担图分区。原项目基于 ROS Noetic / RotorS，需要适配当前 Jazzy / Gazebo 接口。

本项目方案是两者思想的组合设计，不能标注为原算法完整复现，也不能直接沿用论文性能数字。引入原代码时另核对各目录许可证和第三方求解器条件；当前只做设计，不复制外部算法代码。

## 当前代码必须解决的缺口

1. formation_node.py 订阅唯一 /swarm/path，并给三机施加固定 OFFSETS；独立搜索需要每机自己的任务与参考轨迹执行器。
2. candidate_pool_node.py 的里程计、目标和路径话题硬编码为 swarm / drone_0；改为相对话题、按 drone_i 命名空间实例化，并参数化起点和净空。
3. next_project/core/topology.py 是编队相对位置拓扑；core/planning/voronoi_region.py 是局部绕障稳定性代理，均不能当作环境连通图或多机任务分区。
4. 当前规划器可读取完整障碍 JSON，没有未知/已知空间与真实搜索完成判据。不得用全图真值计算前沿和信息增益后声称未知环境探索。
5. 现有烟雾验收固定三机同目标偏移，需要单独搜索验收；旧编队模式保留为回归基线。

## 建议架构

每机链路：传感观测 → 局部占据图/前沿 → 动态拓扑图 → 任务分配与任务执行器 → 现有候选路径评估池 → 参考轨迹执行器 → C++ 控制器 → Gazebo。

新增模块建议拆为 annual_exploration 包；可复用算法内核放 next_project/core/exploration。与现有 annual_swarm 控制、模型和路径评估接口分开维护。

| 模块 | 职责 | 主要输出 |
|---|---|---|
| observation / frontier | 由可见观测更新 unknown/free/occupied、聚类前沿、生成安全观测位姿 | frontier 与可见信息增益 |
| topology | 增量维护探索图、边的可通行性与地图版本 | topo delta / snapshot |
| task_allocator | 图代价初始归属、负载均衡、成对任务协商 | 带版本的任务序列 |
| mission_executor | 接受/取消任务、完成确认、失败反馈 | 每机 goal、任务状态 |
| per-drone portfolio | 原多规划器/多路径评分与五条备选 | 每机 path、可达性与路线代价 |
| trajectory_executor / deconfliction | 独立跟踪、时空冲突检查、窄通道通行协调 | 每机 target / trajectory_target |
| exploration_metrics | 覆盖率、重复搜索、分配/通信及安全指标 | 搜索验收记录 |

全局只有仿真评测器可使用完整世界真值作为覆盖率分母；运行时决策使用观测图。第一阶段允许标记为“已知地图覆盖搜索”的模式，验证分工闭环；不能将其与未知地图探索结果混报。

## MR-DTG 风格图设计

采用稳定 ID 的可通行区域/历史锚点 H 类节点、前沿及观测任务 F 类节点，以及经过局部规划与净空检查的连接边。前沿消失使用失效记录，不让迟到消息重新激活旧任务。

节点包含 node_id、来源 drone_id、创建序列、位置/区域、观测时间、信息增益、状态和版本。任务包含 task_id、目标观测位姿、状态、owner、allocation_epoch、目标版本和已观测进度。边包含端点、路径长度/预计行驶时间、净空、有效版本及阻塞状态；位置近不代表存在可通行边。

分区采用图最短路代价，而非穿墙的欧氏距离。图断连的目标记为不可达，不用有限大代价掩盖可达性。动态障碍使相关边失效，先局部修复，再更新受影响任务归属。只交换变更节点/边与必要任务状态；同时提供快照重同步以恢复漏包。

跨机地图首版可假设共享 world 坐标与 Gazebo 里程计，必须写入实验假设。跨机节点去重不能仅靠相同 ID；需要空间关联和一致版本规则，避免同一前沿被多次分配。

## 分配策略：GVP 初分区 + RACER 风格成对再分配

保留四个可选策略作为可比较实现目标：nearest_frontier、graph_voronoi、pairwise_route_balance、gvp_pairwise。后二者在未完成原 CVRP 实现前应明确命名为启发式版本。

先由图运动代价生成任务归属与局部访问序列；再在相邻、负载差异明显的 UAV 对之间，优化其任务集合的转移、交换及访问顺序。每个任务最多一个已确认所有者；无人可达的任务保持待处理并公开原因。

拟用目标函数为：最大预计剩余完成时间 + 加权总行驶时间 + 任务转移惩罚。单机负载含图行驶时间和区域剩余观测工作量，不只统计任务数。信息增益用于任务价值/次序；必须有工作量下限和饥饿处理，不能永久跳过低收益区域。电池约束只有接入可信状态或明确能耗模型后才启用。

上述组合目标是本项目设计，不是原论文公式。时间、信息增益等量先按固定尺度归一化，权重以配置公开。

触发：新前沿、任务完成、目标失效、图边阻塞、工作量失衡、执行失败，以及受控的低频复核。分配更新慢于避障和控制；采用最小收益阈值、冷却期和短期任务承诺减少来回改派。初始可试 1 Hz 复核，阈值需实验确定。

成对协商至少携带 proposal_id、双方任务版本、图版本及收益；准备、确认、提交过程须幂等，不能双方一收到提议就各自改 owner。并行协商采用确定性顺序和版本比较，过期提议拒绝。

异步失联不能仅凭本地超时就证明另一机退出：首版失联任务标为 uncertain，并保留可能占用的区域。安全接管需要明确的退出/到期停止协议和时钟假设；网络分区下不能无条件同时保证任务唯一归属和持续接管。中心化原型若用单一提交仲裁，须明确其不具备 RACER 的去中心化性质。

## 与五条备选路径的关系

每机维护“1 条执行路径 + 最多 5 条安全且不同的备选”，备选属于当前任务。路径缓存键至少包含 drone_id、task_id、goal_revision、map_version，任务更换后禁止误用旧目标的缓存。

障碍出现先暂停参考推进、验证并切换同任务备选；有安全路径则继续任务。全部备选失效时局部重规划；仍不可达或代价显著上升才向任务分配器反馈，触发跨机改派，避免每次绕障都打乱分工。

路径质量评分解决“怎样飞往一个目标”；任务分配解决“谁先搜索哪些区域”。拓扑边可缓存规划器估计的时间和净空，先做廉价图筛选，再对少量候选执行精细规划，避免每轮对所有 UAV×前沿生成完整候选池。

单机独立搜索使用机体包络加余量的净空，不沿用当前整队 1.9 m 参数。无人机间的时空碰撞必须另查；静态路径互不碰障不代表机间不相撞。窄通道预留/让行、轨迹时域冲突检查和执行超时处理是进入真实多机 Gazebo 搜索前的门槛。

## 实施顺序与验收

1. 独立导航与已知图原型：参数化每机 planner/执行器，保留旧编队入口；新增合成拓扑图与任务分配核心测试。已知地图任务完成先用明确的区域观测覆盖条件，单纯到点只能算 waypoint reached。
2. 真实三机覆盖搜索：Gazebo 独立目标、前沿/观测模型、图增量更新、每机五备选、任务改派、机间避碰。日志区分目标到达、观测完成和区域探索完成。
3. 观测驱动未知探索：接入 Gazebo 量测或有遮挡射线的有限视野传感模型；全图只交给仿真与评测。再扩展深度/激光占据图。
4. 分布式协商：图差量同步、迟到/重复/乱序消息、断连重连、任务归属与安全接管，验证后再描述去中心化能力。

核心测试：穿墙近但图上远；断连节点；前沿生成/消失；任务拆分/合并；版本回滚拒绝；并发协商；低收益区域最终处理；全部不可达；旧任务路径结果丢弃；重连去重。飞行测试：窄走廊会车、障碍堵路后先换路径再改派、暂停一机后受控接管、所有目标不可达时安全悬停。

对照固定地图族、机数、种子、传感器、规划/控制器、路径池和安全门限。比较最近前沿、纯 GVP、成对负载优化、组合方案；增加“无再分配”“无迟滞”“不同备选数量”的消融。原算法复现与本项目启发式必须在表中分开标识。

主要指标：T90/T95、预算内最终覆盖率、未完成任务数、重复覆盖率、各机工作量差异、总航程、任务转移次数、分配延迟、实际序列化通信字节、最小机间距及碰撞。未达到覆盖阈值的运行报告失败/超时，不从耗时统计中静默删除；报告不同地图与多种子分布。当前尚无这些实验结果。
