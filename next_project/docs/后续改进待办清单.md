## 三、A 线：仿真系统技术改进

### A1. FIRI 多段走廊轨迹优化 ✅ | 已完成 | 优先级 P1

- **目标**：将分段 `FIRICorridor` 串联为连续、低曲率、满足速度/加速度约束的时间化轨迹
- **涉及文件**：`core/planning/firi.py`、新增 `core/planning/trajectory_optimizer.py`
- **方案**：求解最小 snap/jerk 或二次规划轨迹，在各凸走廊内插值/平滑
- **验收**：最大曲率下降、leader 跟踪 RMS 下降、碰撞=0、耗时可控
- **回退**：当前 FIRI 点投影和弧长重采样
- **对应评审维度**：项目创新（技术深度、解决实际需求）
- **落地状态**：已形成工程化 FIRI-style corridor refinement、轨迹质量指标与 C++ 结果字段同步。当前实现不宣称完整 MVIE / GCOPTER 论文复现，作为可解释轨迹平滑和可行性评估链路使用。

### A2. MPC 跟踪可行性评估 ✅ | 已完成 | 优先级 P1

- **目标**：评估轻量 MPC 轨迹跟踪层是否值得引入（不直接替换现有控制器）
- **涉及文件**：新增 `core/planning/mpc_tracker.py` 或控制器扩展
- **方案**：先做离线轨迹后处理实验，收集跟踪 RMS、控制输入饱和度等数据
- **验收**：有数据支撑是否继续推进
- **回退**：继续使用 Backstepping + SMC
- **落地状态**：已加入轻量 MPC 可行性评估输出，包括 `tracking_rms_proxy`、速度/加速度约束违反量、饱和比例和建议字段；保持“评估层”定位，不替换现有控制器。

### A3. Voronoi 分区策略原型 ✅ | 已完成 | 优先级 P2

- **目标**：多障碍环境基于 Voronoi 分区稳定选择避障侧，减少目标切换振荡
- **涉及文件**：`core/planning/replanner.py`、可能新增 `core/planning/voronoi_region.py`
- **验收**：重规划抖动减少、路径长度不显著增加
- **回退**：仅在 2D 水平投影启用
- **落地状态**：Python/C++ 已同步 Voronoi region scoring，重规划候选可根据区域稳定性加权，保留默认关闭/低权重的实验开关。

### A4. MADDPG 资料补齐后再评估 ⏸ | 暂时挂起 | 优先级 P2

- PDF 为空，仅保留题名级引用，不进入短期主线
- **当前结论**：MADDPG 可作为未来“学习型多机协同策略”候选研究模块，用于多智能体协同避障、编队保持和复杂交互策略学习；但当前缺少可复现实验细节，训练成本高，稳定性和 Python/C++ 同步成本不可控，因此不纳入本轮 A 线工程闭环。

### A5. 动态障碍类别与差异化衰减 ✅ | 已完成 | 低优先级

- 来源：MIIM 文献后续，为不同类型动态障碍设置差异化 TTL 和衰减策略
- **落地状态**：传感器发现障碍支持 transient / persistent 分类、命中计数和差异化 TTL；Python `WindowReplanner` 与 C++ `replanner.hpp` / obstacle scenario 配置已同步。

### A6. 容错拓扑更细指标 ✅ | 已完成 | 低优先级

- 增加能耗与连通性指标（代数连通度 λ₂ 等）
- **落地状态**：新增 `topology_metrics` 结果字段，输出 `mean/min/final_algebraic_connectivity`、leader/follower 控制能耗代理、故障事件计数和重构事件计数；Python/C++ 输出与 schema 已对齐。

### A 线阶段结论（2026-05-23）

A1/A2/A3/A5/A6 已完成工程闭环并同步到 Python/C++ 关键输出；A4 因资料不可复现暂时挂起。当前 A 线可以作为“仿真系统技术改进”阶段成果归档，后续主优先级转向 B 线 3DGS 重建端整合与 C 线参赛材料。

## 四、B 线：3DGS 重建端整合

### B1. 绝对尺度恢复 ⏳ | 预估 2-3 周 | 最高优先级

- **目标**：将 3DGS 输出的相对坐标系点云转换到米级世界坐标
- **方案**：IMU 积分估计位移 + ArUco 码标定板 + 建筑规范约束（门高 2.1m、走廊宽 1.5m）
- **涉及文件**：`core/model_importer.py`
- **风险**：ICP 不收敛 → 准备手工标定双保险

### B2. 坐标系统一 ⏳ | 预估 3-5 天 | 高优先级

- **目标**：OpenCV 坐标系（Y 向下）→ 航空坐标系（Z 向上）
- **方案**：绕 X 轴旋转 180° 的轴向翻转矩阵，在 `model_importer.py` 中增加坐标系参数选项
- **涉及文件**：`core/model_importer.py`

### B3. 端到端自动化脚本 ⏳ | 预估 1-2 周 | 中优先级

- **目标**：「拍照 → 重建 → 仿真 → 报告」全流水线一键执行
- **方案**：编排 auto_gs.py + 仿真入口 + 报告生成，总耗时目标 < 10 分钟/场景
- **对应评审维度**：产业价值（落地前景、可验证性）

### B4. 3DGS 端测试补充 ⏳ | 高优先级

- **目标**：补齐 3DGS 重建端的自动化测试空白
- **内容**：
  - Spann3R 推理和点云处理的 pytest 用例
  - 模拟上传 → 重建 → 训练的完整流程测试
  - 前端小程序测试
  - 性能测试（重建速度基准）

### B5. 融合系统四层测试 ⏳ | 中优先级

- L1 数据层：验证 3DGS 输出 PLY 可正确解析并体素化

- L3 系统层：端到端验证全流水线
- L4 压力测试：大规模场景编队规划性能

### B6. 实时性优化 ⏳ | 预估 2 周 | 中优先级

- **方案**：关键帧降采样（kf_every 10→20-30）、模型量化、C++ 重建加速
